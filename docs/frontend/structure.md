# Frontend structure

## Overview

The SPA lives under `resources/js/`. This page is the map of that tree and how a request becomes a
rendered page.

```text
resources/js/
  app.tsx            # entrypoint: createInertiaApp, providers, theme init
  pages/             # Inertia pages (resolved by name)
  layouts/           # shared page layouts
  components/        # custom components + ui/ (shadcn base)
  hooks/             # custom React hooks
  lib/               # utilities (cn, toUrl)
  types/             # TypeScript types (User, Auth, SharedData, …)
  actions/           # generated by Wayfinder (controllers)
  routes/            # generated by Wayfinder (routes)
  wayfinder/         # Wayfinder type helpers
resources/css/app.css   # Tailwind 4 + theme
resources/views/app.blade.php  # Inertia root template
```

## The render path

1. A backend route renders an Inertia page, e.g. `Inertia::render('dashboard')` (`routes/web.php`).
2. `resources/views/app.blade.php` is the root HTML. It sets the `dark` class from the `appearance`
   cookie, loads the fonts (Instrument Sans via Bunny) and `@vite`s `app.css`, `app.tsx` and the page
   component.
3. `resources/js/app.tsx` resolves the page from `resources/js/pages/{name}.tsx` and mounts it inside
   the global providers.

## Pages

Pages live under `resources/js/pages/`, grouped by area:

| Group              | Pages                                                                                                                                                   |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Public             | `welcome.tsx`, `dashboard.tsx`                                                                                                                          |
| Auth               | `auth/login`, `auth/register`, `auth/forgot-password`, `auth/reset-password`, `auth/verify-email`, `auth/confirm-password`, `auth/two-factor-challenge` |
| User control panel | `ucp/profile`, `ucp/password`, `ucp/security`, `ucp/sessions`                                                                                           |
| Errors             | `errors/403`, `errors/404`, `errors/419`, `errors/429`, `errors/500`, `errors/503`                                                                      |

The auth and UCP pages back the routes documented in
[../authentication/index.md](../authentication/index.md); the error pages back the Inertia exception
rendering in [../architecture/app-bootstrap.md](../architecture/app-bootstrap.md).

## Layouts

A page declares its layout with Inertia v3's `Page.layout = (page) => <Layout>{page}</Layout>` pattern.
There are three layouts in `resources/js/layouts/`:

| Layout            | Used by                               | Shape                               |
| ----------------- | ------------------------------------- | ----------------------------------- |
| `app-layout.tsx`  | Dashboard, authenticated pages        | Sticky header + centered main.      |
| `auth-layout.tsx` | Login, register, password reset       | Centered card with logo and footer. |
| `ucp-layout.tsx`  | Profile, password, security, sessions | Heading + sidebar + content.        |

## Types

`resources/js/types/index.ts` defines the shared types consumed from Inertia props — `User`, `Auth`,
`SharedData` (mirrors `HandleInertiaRequests`), `Passkey`, `SessionRecord`, `NavItem`. Keep them in
sync with the backend shared props.
